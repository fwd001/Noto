# ADR-0016: 本地静态加密（未决）

## 状态
日期：2026-09-25
状态：**Proposed**（本 ADR 不做决定，需人工确认合规要求）

## 背景
内网/警务环境常把"落盘数据必须加密"作为验收条件。当前设计下本地 SQLite 为明文，依赖操作系统全盘加密（BitLocker / FileVault）满足该要求；WebDAV 侧的端到端加密结构已由 ADR-0002 预留，但**默认不启用**，因此"服务器上看不到明文"与"本地磁盘上看不到明文"是两件不同的事。二者的合规判定路径也不同，不能互相替代。

## 决策
本 ADR **不做决定**，只固定以下三点，避免讨论发散：
1. 待评估的三个选项见下节，评估口径为"能否通过目标环境的合规检查"，不是"实现难度"。
2. 在合规要求确认之前，不引入任何加密依赖、不改 `notera-store` 的连接层、不改备份格式。
3. 若任一选项被采纳，必须**同步修订**：DATA-MODEL.md（连接参数与 DDL 不变式）、备份/恢复流程（FT-IO-*）、导出格式（明文导出的取舍）、测试矩阵（L1 组件与 L4 崩溃点全部要重跑）。
4. 明确记录当前状态供文档引用：本地明文 + 依赖 OS 全盘加密；凭据从不落库（存系统钥匙串）。

## 备选方案与被否决的原因
这里是"待选"而非"已否决"，列出代价供决策：
- ① 依赖 OS 全盘加密：代价最低（零代码、零性能损失、备份流程不变）；风险是合规检查可能不接受——它保护的是"机器丢了"，不保护"文件被复制走"，且无法证明应用层做了控制。
- ② 引入 SQLCipher：替换 SQLite 依赖（rusqlite bundled 路径全变）。代价：bundled 构建与四端交叉编译风险（Android NDK / iOS 静态库）、性能下降、备份/恢复与迁移（ADR-0012 全部契约）要重做、`user_version` 与密钥派生的顺序耦合需新契约。目前未实测任何一项。
- ③ 字段级加密 `notes.doc`：折中——只加密正文，索引与派生列（`title`/`plain_text`/`summary`）保持明文。代价：搜索能力保留但**泄露元数据**（标题、正文摘要、字数全在明文里），且 `note_revisions.doc`、`sync_operations` payload 快照都要一并处理；密钥管理（换设备、恢复）仍是未解问题。

## 后果
正面：问题的边界与影响面被写清，决策只需回答一个合规问题而不是重做架构评审。
代价：
- 这是一个开放项：在决定前，`docs/` 里"数据安全"的表述必须始终区分"传输/远端"与"本地静态"两层，不能笼统说"已加密"。
- 若走 ② 或 ③，Phase 1 已写的存储层要返工（连接工厂、备份、迁移执行器）；越晚决定返工面积越大，因此需要尽早取得合规口径。

## 验证方式
- 决策前：以书面合规条款为准（哪一层要求加密、是否接受 OS 全盘加密、密钥交付与恢复要求），把结论原文记入 `docs/evidence/`，本 ADR 状态据此改为 Accepted 或 Superseded。
- 若采纳 ②：探针必须实测 SQLCipher 在 `aarch64-linux-android` 与 `aarch64-apple-darwin` 上可编译可链接（当前本机无相应工具链，属 BLOCKED）；并实测加密库上 ADR-0015 的检索性能预算是否仍成立。
- 若采纳 ③：必须存在"拷走 SQLite 文件后 `notes.doc` 不可读、但 `title` 可读"的黑盒用例，以及密钥丢失路径的用户可见行为定义（不得静默丢内容）。
- 任一选项落地后：备份文件可在新装环境恢复（FT-IO 系列）、迁移链（M1–M4）全绿，才算该决策成立。
